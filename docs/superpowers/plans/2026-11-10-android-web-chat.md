# Android-First Eve Web Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a private, Android-friendly browser chat connected to a real Eve planning agent, with streaming replies and durable session URLs.

**Architecture:** Extend the existing Eve/TypeScript repository using Eve's official Web Chat channel scaffold and its generated Next.js client. Keep the agent planning-only, use Eve durable sessions, and require authenticated production access through Sign in with Vercel when the linked project supports it; otherwise block production exposure.

**Tech Stack:** Node.js 24, npm, Eve (existing `^1.0.0-rc.6` baseline), TypeScript, generated Next.js/Eve Web Chat integration, and the smallest test tooling compatible with the generated scaffold.

**Spec:** `docs/superpowers/specs/2026-11-10-android-web-chat-design.md`

## Global Constraints

- Node.js 24 or newer; preserve the existing npm project and Eve dependency unless the official scaffold proves a compatible adjustment is required.
- Android-first responsive web app; minimum tested viewport width is 360 CSS pixels.
- Use the official Eve Web Chat integration and generated client; do not invent a parallel chat transport.
- Agent is planning-only; no GitHub tools, repository writes, shell execution, deployment tools, or external-action tools.
- No production deployment or paid model calls without explicit user approval.
- No secrets in source control, test fixtures, logs, or committed environment files.
- Production browser access must fail closed unless a real authentication mechanism is configured.
- Preserve existing agent instructions and CI behavior while making type-checking unconditional once TypeScript source exists.

## Review Focus

- Missing or malformed model configuration: show a safe actionable error and never expose credentials.
- Unauthenticated production request: reject before agent execution.
- Invalid or unknown session ID in a URL: show a recoverable not-found/error state without silently creating a different conversation.
- Stream interrupted or network lost: preserve the current transcript and allow retry/reconnect without duplicating a user message.
- Narrow viewport with Android keyboard open: composer remains visible/usable and no horizontal overflow occurs.
